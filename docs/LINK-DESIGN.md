# 3 つの手の連動（設計。まだ作っていない）

2026-11-26 にカオルと決めた設計。**まだ作っていない**。今日の窓と許可の設計（[ASK-DESIGN.md](ASK-DESIGN.md)）と合わせて、あとでまとめて作る。作る前に、下の「PC で確かめること」を記録を取って確かめる。

PC・WEB（Chrome）・iPhone を「3 つの手」と呼ぶ。PC と WEB は同じ常駐役（pc-agent）の中で動き、許可と記録も共通。iPhone は別の拡張機能（iphone-mcp）で、共通なのはスイッチの窓だけ。これを連動させ、まとめて動かせる（オーケストレーション）ようにする。

## 1. 土台：記録と窓を 1 本にする（最初にやる）

### TIMELINE（時系列の記録）

- 3 つの手の操作を、全部同じ形で 1 本の記録に残す
- 1 行：時刻・どの手か・何をしたか（ふつうの言葉）・Claude の説明・結果・戻せるか
- 置き場所 `devkit\hands\timeline\日付.jsonl`。PC の中だけ（repo に入れない）
- LIVE 窓・朝の報告・「さっき何した？」の答えは、全部ここから作る
- iPhone の操作の記録（ASK-DESIGN.md の「操作の記録」）もここに入る

### iPhone の道具のつなぎ方

- まずは iPhone の道具が常駐役に「やったこと」を知らせるだけにする（変更は小さい）
- iPhone との接続そのものを常駐役に移すかは、あとで記録を見て決める。今の拡張機能が起動し直してつなぎ直す頻度を server.log で数え、困っていなければ移さない（大きな作り直しで、壊れる場所も増える）

## 2. 連動の部品は 3 つに絞る

細かい機能を増やさず、組み合わせて使う部品にする。

| 部品 | 中身 |
| --- | --- |
| SEND（送る） | ページ・文字（クリップボード）・ファイルを、ある手から別の手へ（PC ⇄ iPhone、Chrome ⇄ Safari） |
| COMPARE（並べる） | 同じページを PC と iPhone で開いて画面を撮り、1 枚に並べる（スマホでの見え方の確認） |
| CALL（呼ぶ） | iPhone のショートカット、PC の台本を呼ぶ |

## 3. RECIPE（台本）：まとめて動かす

- 機器をまたぐ手順を書いて、常駐役が 1 回の呼び出しで最後まで動かす。前の手の結果を次の手に渡せる（例：Chrome の今のページの URL → iPhone の Safari で開く → 両方の画面を撮る）。Claude との往復が減るので、速く、言葉（トークン）も少ない
- **手ごとの守りは 1 手ずつ通す**：スイッチと、ASK-DESIGN.md の作業の分け方（A〜E）を 1 手ずつ通す。台本は 10 分 許可を使えない。B（箱）と E（最後のボタンはカオル）の手は、そこでカオルを待つ。台本を守りの抜け道にしない
- **失敗したら止まる**：その時の両方の画面を撮り、LIVE 窓に出して記録に残す。やり直すのは「読むだけ」の手に限る
- **同時に動かさない**：手ごとに「使用中」の札を持ち、Claude の操作と台本がぶつからないようにする
- **iPhone がつながっていないとき**：「つながったら続ける」か「やめる」かを台本ごとに決める。黙って待ち続けない
- よく使う台本は名前を付けて保存する。中身に個人の情報が入りうるので置き場所は PC の中（`devkit\hands\recipes\`）。repo には例だけ置く

## 4. WATCH（見張り）：起きたら動く

- 「○○が起きたら、この台本」を、Claude がいなくても常駐役が動かす
- 最初の候補：
  - iPhone を USB でつないだら、1 日 1 回バックアップ（ASK-DESIGN.md の「バックアップ」）
  - iPhone のアプリが落ちたら、記録を PC に取っておく
  - Chrome のダウンロードが終わったら、決めたフォルダへ移す
- 決まり：
  - 使えるのは A（読む）と D（小さくて戻せる変更）の手だけ（ASK-DESIGN.md）。10 分 許可は使えない
  - 関わる手のスイッチが足りないときは動かない
  - スイッチの窓に「AUTO」の段を足し、見張りを全部まとめて止められるようにする
  - **見張りを足す・変えるのは先にカオルに聞く**（ALLOW 窓に中身をふつうの言葉で出す）。見張りは置いたら動き続けるので、Claude が勝手に作れないようにする

## 5. 外からの入口（いちばん最後）

- スマホから「止める」（ASK-DESIGN.md の「あとで考える」C の案）、いつか Siri から呼ぶ（例「PC の空きを調べて」）
- 外から入るものは「見る・止める」だけ
- 2026-11-26 に調べたこと：Apple の公式の MCP サーバーは Mac の Safari（Technology Preview）と Xcode だけで、Windows から iPhone を動かせるものは無い。iOS 27 では Siri が MCP サーバーを呼べるようになったという記事がある（Apple の発表で確かめられたのは App Intents を Siri の AI につなげるところまで）。iPhone → claude-hands の道になるかもしれないが、日本語の Siri で使えるか・外から PC に届く道をどう守るかは未確認

## 守り（連動で新しく出る穴）

1. **ページの文字が iPhone に流れ込む**：Web のページの中身（URL・文字）を台本で iPhone に送ると、悪いページが「これを開け」「これを打て」と仕込める。Web から来た値は送り先でももう一度守りに通し、打ち込みには使わない（開くだけ）
2. **見張りが勝手に増える**：足す・変えるのは先にカオルに聞く（上）
3. 連動を増やすほど、間違えたときの広がりも大きい。見張りは「戻せること」（バックアップ・記録の写し・移す）から始める

## 使い道の例（2026-11-26 に挙げたもの）

- iPhone アプリの自動の試し：PC で直す → 入れる → 起動 → 画面を順に押す → ログと画面を PC に集める（夜の間に全部の画面を試す、も）
- Pythonista のアプリ（CityRank・CoatingAssist など）：PC から iCloud Drive の Pythonista のフォルダに置き、iPhone で URL から起動して確かめる（未確認）
- スマホでの見え方の確認（COMPARE）
- 朝の点検を 1 枚に：PC の空き・不具合、iPhone の空き・電池・最後のバックアップ
- 続きをもう一方で：スマホで見ていたページを PC の Chrome で、またはその逆
- iPhone のスクショを PC の決めたフォルダに日付で集める
- 「出かける前」の 1 回：PC の作業を片付けてスリープ、iPhone の自動ロックを戻す
- PC のサイトで 2 段階認証のコードが要るとき、LIVE 窓に「iPhone を見てください」（コードを入れるのはカオル）
- せどり：店で JAN を撮る → 家の PC が調べる → スマホに結果（外では USB が無いので、iCloud と通知の新しい道が要る。5 の入口と合わせて考える）

## 道具の数（2026-11-27）

- 今は 43 個（iPhone 23・PC 15・ブラウザ 5）。使える道具が 30〜50 個を超えると、Claude が道具を選び間違えやすくなる（Anthropic も言っている。目安は 40 個あたり）。道具の説明は使わなくても毎回読み込まれるので、トークンもかかる
- 方針（カオル「整理しよう。あくまで可能で適切な範囲で」）：**数を減らすこと自体を目的にしない**。まとめても迷わず使える所だけまとめる。目安は 30 個台（見積もり 34 個くらい）
- 新しい機能は、なるべく道具を増やさずに入れる：
  - 箱で試すのは、pc_powershell などに「箱で」という指定を足す
  - バックアップの状態は pc_status・iphone_status に出す
  - TIMELINE を読む・まとめて戻すは 1 つの道具（例：hands）
  - SEND・COMPARE・CALL は RECIPE の 1 手として書けるようにし、hands_run 1 つ
  - 見張りは hands_watch 1 つ
- 今の道具の棚卸しの候補：iPhone の細かい操作（タップ・文字でタップ・スワイプ・ピンチ・スクロール・文字を打つ・ボタン・確認の窓・待つ・まとめて動かす）を 1 つの iphone_do に（browser_do と同じ形。browser_do はうまく動いている）。PC の画面の操作（部品を押す・キーを押す・開く・窓）を 1 つの pc_do に
- まとめすぎると 1 つの道具の使い方が複雑になり、かえって使い間違える。まとめるたびに、前の会話を知らない Claude で「迷わず使えるか」を試して確かめる。迷うならまとめない
- 一般の MCP（ファイル・ブラウザ・PC の操作など）は足さない（claude-hands と重なり、似た道具が増えるため）。Claude のアプリのコネクタも、使わないものはオフにしておくとよい

## iPhone の画面の読み方（2026-11-27）

今は画面の画像（1/3 の JPEG・390×844。Claude が読むと 1 枚 400〜500 トークンほど）を主に使い、押す場所が分からないときだけ iphone_elements（WebDriverAgent に部品を全部もらう。ホーム画面で 10 秒ほどと遅い）を使っている。文字で押す iphone_tap_text、Safari の中を文字で読む iphone_web もある。

**ねらい（カオル）**：実現できる範囲で、より速く・より正確に・よりトークンを安く。**いちばん大事なのは、Claude が画面の中身（どのアプリのどの画面か、何が押せるか、オンかオフか・入っている値、ポップアップがあるか）をどれだけ正しく分かるか**。速さとトークンはその次。

- 土台（go-ios ＋ WebDriverAgent）は替えない。Windows から iPhone を動かす道具では go-ios がいちばんの選び方（pymobiledevice3 は Python が要り、できることはほぼ同じ。tidevice・Appium なども中は WebDriverAgent）
- 試す読み方（同じ画面で比べる）：
  1. 今の画像
  2. WebDriverAgent の部品を全部
  3. WebDriverAgent に絞って聞く（この文字・ボタンだけ・見えている所だけ・深さの上限）
  4. go-ios のアクセシビリティの機能（ax。Mac の Accessibility Inspector と同じ API。WebDriverAgent を通さずに読めるかもしれない。試験的な機能なので iOS 27 で動くかを確かめる）
  5. PC の文字認識（Windows に付いている Windows.Media.Ocr。画面の画像から文字と位置を取り出す。部品の情報が無いアプリでも読める。日本語の精度・速さと、道具から呼べるかを確かめる）
- 比べ方（とにかくログ）：設定・ホーム・DevKit・LiveContainer・地図など数種類の画面で、①Claude の分かり方（前の会話を知らない Claude に、画面のこと（どの画面か・押せるもの・オンオフ・値）を聞いて正しく答えられるか）②かかった時間 ③Claude に渡す長さ（トークン）を記録する。①を最優先に決める
- 形の案：1 つに決めず組み合わせる。まず部品と文字で「画面のまとめ」（アプリと画面の名前・押せる部品と状態・見えている文字）を短く返し、部品の情報が無い所は文字認識で補い、それでも分からないときだけ画像。押したあとは画像の代わりに「何が変わったか」を短く返す
- 道具を増やさない（「道具の数」）：今の iphone_elements・iphone_screenshot の中の選び方として入れる
