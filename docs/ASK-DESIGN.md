## 2. 作業の分け方（どの道かは道具が決める）

| 道 | 中身 | 流れ |
| --- | --- | --- |
| A | 読む・調べる | 本物でそのまま |
| B | 試せる変更（ソフトを入れる・ファイルをまとめて変える・アプリの設定・台本） | 箱で先にやる → 道具が自動で確かめる → カオルが箱の中で使ってみる（TRY の窓）→［本物に入れる］か［捨てる］ |
| C | 箱で試せない変更（Windows 全体の設定） | 控え（Git）を取る → 本物でやる → 道具が自動で確かめる → だめなら自動で戻す → DONE で報告 |
| D | 小さくて戻せる変更（ごみ箱へ送る・決めた操作） | そのままやる → 取り置きと記録 → DONE で報告。判断は要らない |
| E | 戻せないもの（送る・お金・ログイン・投稿） | Claude は**最後のボタンの手前まで**進める。カオルが実物（書き上がったメール・入力済みの注文の画面）を見て自分で押す |

- **道具が見分けられない操作は C か E**。D に入るのは決めた操作の一覧に載っているものだけ
- **E で押すボタンが無いもの**（パスワードのファイルを読む、など）だけ ALLOW の窓で聞く。出るのはまれ。範囲と時間は今のまま（2026-11-26 カオル）：10 分間、全部の種類が通る。返事を待つのは 80 秒。UAC を通る（Claude には押せない）
- E の作業中は、送信に当たるキー（Enter など）を押さない（Enter だけで送られるページがあるため）
- **戻せるように見えて戻せないもの**は E：送ったメッセージ・メール・買い物・投稿／iCloud で同期されるもの（ほかの機器に先にうつる）／戻すのにパスワードや 2 段階認証が要るもの（サインアウト・Face ID）／アプリを消す・リセット／パスワード・鍵を読む
- 戻したら、道具がもう一度値を読んで、元と同じかを確かめる

### 道具の自動の確かめ（B・C）

- アプリが起動するか、エラーの記録が増えていないか、決めた場所の外を触っていないか、箱の中で外へ通信しようとしなかったか
- おかしければ止めて、自動で戻す
- 万能ではない（数日後に出る不具合は、まとめて戻す・バックアップで受け止める）

### 箱（B）

- 箱の候補：①Sandboxie-Plus（オープンソース・軽い）②仮想 PC（VirtualBox など。重いがどの版でも動く）。Windows サンドボックスは Pro 版だけなので使えない（カオルの PC は Home 版）。どれも動かなければ、B は C と同じやり方にする
- 箱の中では：増やしたファイルは箱の中だけにできる／書き換えると箱の中の写しだけが変わる／消すと箱の中で消えたことになる（本物は残る）／ソフトを入れる・動かすのも箱の中（アプリの設定も箱の中だけ）。Windows の深いところ（ドライバー・サービス）を入れるソフトは、箱では入らないことがある
- 箱の設定：ネットを切る（つなぐときはカオルに聞く）。パスワード・鍵・バックアップ・取り置き・Git の記録の場所は、箱から見えないようにする（箱の中のアプリも、ふつうは本物のファイルを読めるため）
- **ネットから来たファイル**（Windows の「ネットから来た」印が付いたもの）は、必ず箱で動かす。箱に入れる前に Windows Defender の検査を自動でかける
- カオルの repo（claude-hands など）を GitHub が作った版は、中身が一致すれば箱を通さなくてよい
- ［本物に入れる］：箱で試したのと同じファイルだけを入れる（中身の一致を確かめる）。作ったファイルは本物の場所へ移す。ソフトは本物にもう一度入れ直す（UAC が出る）。箱で消したものは、本物の側では取り置きへ送る（Sandboxie には消したことを本物に移す仕組みが無い見込み。確かめる）
- TRY の窓には、ネットありでは試していないことをはっきり出す
- 終わったら箱を空にする（写しがたまってふくらむため）

## 3. 窓（判断させるのは TRY と ALLOW だけ）

| 窓 | 役目 |
| --- | --- |
| SWITCH | 今の操作スイッチ（iPhone・PC・WEB の OFF・VIEW・OPERATE と ALLOW）を新しい見た目にしたもの |
| TRY | 箱で試した結果（増えた・変わった・消えた・外への通信）を出し、使ってみてもらう。［箱の中で開く］［本物に入れる］［捨てる］ |
| ALLOW | まれな窓。WHAT（しようとしていること）・WHY（Claude の説明）・IF ALLOWED（許可すると）を出す |
| DONE | 作業が終わったら、ふつうの言葉で報告し［まとめて戻す］を付ける。中身は Claude の説明ではなく、記録と Git から作る |
| LIVE | 画面の隅に「Claude が動いている」ことだけを出す。ボタンは［止める］だけ（押さなくても困らない）。15 秒で小さな丸い形にたたむ |

- 窓の中身の書き方
  - **しようとしていること**：道具が呼ばれた中身から作る。Claude には書かせない。「読む・変える・消す・送る・開く・押す・打つ」と相手（Chrome のパスワードのファイル・Windows の設定・銀行のページなど）を組み合わせ、命令やファイルの場所の文字列はそのまま出さない（道具の中に言い換えの表を持つ。表の出来が要なので手間をかける）。表に無い操作は隠さずに「よく分からない操作（道具の名前）」と出す
  - **Claude の説明**：窓が出るときだけ要る。説明が無いと、道具は窓を出さずにすぐ「説明を付けて呼び直して」と Claude に返す。100 字まで。記号の多い文（命令っぽいもの）は受け付けず書き直させる。その許可が続く間にやることのまとまりで書く
  - 窓は「しようとしていること」を大きく、Claude の説明を小さく出す（説明は間違いや、読んだページにそそのかされた可能性がある。2 つが合っていなければ断る目安）
  - スイッチの窓（見るだけ・操作も可の頼み）も同じ形。許可すると：「iPhone が『操作も可』になります。30 分使わなければ OFF に戻ります」
  - 頼みが同時に 2 つ来たら「ほかに 1 件待っています」と出す
- 音は、TRY と ALLOW がカオルを待つときだけ鳴らす（Windows の通知音）
- LIVE の窓はフォーカスを取らず、画面の隅に出す。Claude が画面を撮る・座標で押すときは一瞬隠す
- ［止める］：全部のスイッチを OFF、動いている操作は打ち切り（iPhone のバックアップは最後まで取る）。Claude には「カオルが止めた」と返り、Claude はやり直さずにチャットで聞く
- ALLOW を断る・時間切れ：Claude に「カオルが断った」と返る。同じ操作をやり直さず、チャットで聞く
- 許可・断る・説明は記録に残す

- iPhone の窓で許可を押したとき、前のバックアップから 1 日以上たっていれば裏で取る（Claude の作業は止めない）。終わったら・失敗したら LIVE の窓で伝える。窓には「BACKUP：最後は ○/○。許可したら裏で取ります」と出す

- 暗号化オン（最初にオンにするときの iPhone のパスコードと、暗号のパスワードはカオル）。iPhone で毎回パスコードを聞かれるなら、窓に「iPhone でパスコードを入れてください」と出す

- 戻すのは iPhone を丸ごと上書きするので E。カオルだけがやる

## 6. 穴のふさぎ（2026-11-27 に見直した）

- **窓の偽物**：頼み（requests）に、道具だけが知る合言葉で署名する。窓は署名の無い頼みを捨てる。合言葉と requests の置き場所は 1 の守られた場所
- **Claude が窓を押す**：claude-hands の道具（pc_ui_do・pc_keys・click_xy）はスイッチの窓の部品を押せないようにする。computer use は押せてしまうので Claude の決まりにも残す。ALLOW は UAC で守られている
- **箱のすり抜け**：ネットから来たファイルは必ず箱（上の「箱」）
- **まとめて戻すと、カオルの後の作業を消す**：戻す前に「Claude のあとで変わっていないか」を確かめ、変わっていればそこは戻さずに知らせる
- **台本と見張りが 10 分 許可を使う**：台本と見張りは 10 分 許可を使えない。見張りは A と D だけ（LINK-DESIGN.md）
- **Web から来た文字を iPhone に打ち込む**：打ち込みには使わない（開くだけ）
- **カオルが留守**：B と E は帰るまで待つ。Claude はほかの部分を先に進めて、待っているものを DONE の報告にまとめる。スマホから許可する道は作らない（偽物を作られやすい）

### 残る危なさ（ふさげないもの）

- 文字で見る守りは「うっかり止め」。わざと工夫すれば抜けられる（例：カオルの普通のファイルを読んで外へ送る）。記録と Claude の決まりで補う
- 読んだページにだまされた Claude が、許された範囲の中で変なことをする可能性。戻せる仕組みと記録で受け止める
- 道具の自動の確かめは万能ではない
